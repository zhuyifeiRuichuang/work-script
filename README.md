# 关于仓库

标准化部署各类组件用于生产环境，减少开发人员准备环境的时间。

使用前应仔细查看说明和配置文件，确认符合业务需求。

# 关于时间标准化

所有`docker run`命令都应配置`-e TZ=Asia/Shanghai \`指定时区，规避容器与物理机时区时间差异导致组件访问异常问题。

# 针对开源项目的容器化改造思路
以docker工具为例，

梳理项目代码打包的方法。明确代码打包生成的产物。
梳理项目Dockerfile，确认容器镜像打包方法。

组件容器化部署的标准模板，同时生成两个方案
对两个方案的共同要求
容器名字固定
network固定名字
volume固定名字，挂载给数据存储目录，实现数据持久化。
挂载本地配置文件到容器内指定位置，通过配置文件管理组件配置。自动生成模板配置文件。
restart策略使用unless
配置适用于组件的健康检查。
带有明确tag的镜像名称，禁止使用latest，只有latest镜像的可用。
资源限制。明确的CPU和内存配额限制。


方案一
构建docker run命令
结构清晰，内容完整，格式好看。单独在开头写注释，命令行之间不加注释。

方案二
构建compose.yaml文件
内容清晰完整。附带完整说明
依赖关系。多个容器启动时，明确启动顺序。
除非项目十分明确必须使用环境变量，默认使用配置文件。很多环境变量时，用.env文件配置环境变量。
