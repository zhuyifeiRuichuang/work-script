# 说明

标准化部署各类组件用于生产环境，减少开发人员准备环境的时间。

使用前应仔细查看说明和配置文件，确认符合业务需求。

# Docker环境部署组件的标准配置

统一使用compose.yaml部署组件。yaml参考以下标准：

指定的容器名称，服务名称，网络名称，数据卷名称。端口映射。明确tag的容器镜像，不使用latest

环境变量较多时，使用组件各自的env文件。

挂载本地配置文件到容器内，灵活管理配置。

容器内数据存储到数据卷，确保数据持久化。

配置组件健康检查。

明确的容器间启动依赖关系和启动顺序。

配置语言环境。

配置时区。

资源限制。CPU，内存。

重启策略优先使用unless-stopped



特殊配置场景

docker swarm环境专属配置。



# Kubernetes环境部署组件的标准配置

使用yaml文件部署组件时，参考以下标准

指定的namespace，手动创建。不可在yaml里内置namespace

资源占用限制

配置时区。

若使用数据卷，配置存储卷大小，可动态扩展。

镜像拉取策略统一改为IfNotPresent

组件有效的健康检查。



对于标准配置可固化的组件，优化为helm部署方法。
